# REVIEW.md

Review of the starter `app/main.py`. All items below are fixed in the submitted file.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | Not `tz_aware`, so every datetime read back is naive. Naive values silently get treated as local time in later arithmetic. | `punch_out - punch_in` with one naive and one aware value raises `TypeError` (500). | `tz_aware=True`; all code uses aware UTC datetimes and converts at the edges. |
| 2 | `compute_late_minutes` | Builds shift start with `punch_in.replace(hour=...)` on a **UTC** value, so the shift start is 09:30 UTC, not IST. No overnight handling. | Punch-in 09:35 IST gives a nonsense value; punch-in 21:55 for a 22:00-06:00 shift is wrong. | `shift_window()` builds shift start/end as IST instants; `attendance_date()` implements the overnight rule (R1). |
| 3 | `compute_late_minutes` | `int(total_seconds()/60) > 10` is not "strictly more than 10:00". 09:40:30 floors to 10 and is treated as on time. Microseconds are not truncated. | Shift 09:30, punch 09:40:30 should give 10, starter gives 0. | Compare in whole seconds (`> 600`), then floor to minutes from shift start; input is truncated to whole seconds first. |
| 4 | `compute_work_hours` | Python `round()` is banker's rounding on a float, not half-up. No second truncation. | 4.495 h or any exact .xx5 value rounds the wrong way. | `Decimal(seconds)/3600` quantized with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` | Shift end is always on the punch-in's date (wrong for overnight). No 30-minute minimum (R3). `punch_out` naive minus aware `end` raises `TypeError`. | 40 min overtime fine, but 10 min overtime is returned as 10 instead of 0. | Shift end comes from `shift_window()`; floor to minutes and return 0 below 30. |
| 6 | `/health` | Always returns ok even when MongoDB is down. | Stop MongoDB, `/health` still 200. | Pings MongoDB, returns 503 on failure. |
| 7 | `EmployeeIn` / `create_employee` | No validation at all (emp_code format, email, `HH:MM`, valid `joined_on`, `shift_start == shift_end`, lengths). | `{"joined_on": "banana"}` is stored and breaks analytics later. | Pydantic constraints and validators; invalid input gives 422. |
| 8 | `create_employee` | Check-then-insert: two concurrent creates both pass `find_one`. No unique index exists. | Parallel POSTs of the same `emp_code` produce two 201s. | Unique index on `emp_code`; the `DuplicateKeyError` becomes 409. |
| 9 | `create_employee` | `created_at = datetime.now()` is naive local time and the response returns it as an ISO string, not epoch ms. | Response `created_at` is a string. | Stored as UTC datetime, returned as epoch ms. |
| 10 | `list_employees` | `skip = page * page_size` skips the first page. `total` counts the whole collection, ignoring `department`. No sort. No bounds on `page` / `page_size`. | Page 1 returns the wrong rows; `page=0` gives a negative skip (500). | `(page-1)*page_size`, `count_documents(q)`, `sort emp_code`, `Query(ge=1, le=100)`. |
| 11 | `punch_in` | Unknown employee: `emp` is `None` so `emp["shift_start"]` raises (500). Contract wants 404. | POST with a made-up `emp_code`. | Explicit 404. |
| 12 | `punch_in` | `status` accepts any string, including `ABSENT` or garbage. | `{"status": "banana"}` returns 201. | `Literal["PRESENT","WFH","ON_DUTY"]`, 422 otherwise. |
| 13 | `punch_in` | `punched_at` is not validated (seconds, floats and strings accepted). `if body.punched_at` treats `0` as "missing". | `punched_at: 1783312500` (seconds) gives a date in 1970. | Strict int with range check (`EpochMs`); `is not None` instead of truthiness. |
| 14 | `punch_in` | `datetime.fromtimestamp(ms/1000)` uses the **server's local zone** and a float. Attendance date is not the IST date (R1), no overnight rule, no truncation to seconds. | Server in UTC: a 02:00 IST punch-in lands on the previous date. | Convert with integer arithmetic to aware UTC, truncate, derive date via `attendance_date()`. |
| 15 | `punch_in` | Check-then-insert race: two simultaneous punch-ins both pass `find_one`. | Parallel requests give two 201s and duplicate rows. | Unique index on `(emp_code, date)`; `DuplicateKeyError` becomes 409. |
| 16 | `punch_in` response | Returns an `id` (the `_id`) and raw datetimes. Contract forbids `_id` and wants epoch ms. | Response contains `"id"`. | `record_out()` builds the response explicitly. |
| 17 | `list_attendance` | Loads the **whole collection** into memory, sorts and paginates in Python. | Slow and memory-heavy at 100k docs. | Server-side filter, sort, skip and limit backed by indexes. |
| 18 | `list_attendance` | Sorted by `date` only (needs `emp_code` as tiebreaker, so pages are unstable). Returns `_id`, raw datetimes. Legacy documents without `history` / `half_day` come back with the keys missing. | Page boundaries repeat or skip rows; legacy rows break clients. | Sort `(date desc, emp_code asc)`; `record_out()` fills defaults. |
| 19 | `list_attendance` | No validation: bad dates, `date_from > date_to`, unknown `status`, `page_size=10000`. | `?status=banana` returns an empty list instead of 422. | Date parsing helper, `Literal` status, `Query` bounds. |
| 20 | Whole file | No indexes are created, so every query is a collection scan. | `explain` shows `COLLSCAN`. | `ensure_indexes()` at startup, idempotent. |

**Looked at and considered fine:** `load_dotenv()` (does not override real environment variables, which is what the brief asks for). Plain `def` endpoints with the synchronous PyMongo client (FastAPI runs them in a thread pool, so they do not block the event loop; `MongoClient` is thread-safe). Popping `_id` before returning in `create_employee` (it did that correctly; I replaced it with an explicit response builder anyway).
